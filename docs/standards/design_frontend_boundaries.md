# 디자인과 프론트엔드 기준표

UI 변경을 기록할 문서와 프론트엔드 구현 원칙의 기준이다. 하나의 변경이 여러 책임에 걸치면 내용을 나누고 원본을 연결한다. 같은 정책을 여러 문서에 복제하지 않는다.

## Google DESIGN.md 규격

확인일: 2026-09-10. 출처: [Google Labs Code의 DESIGN.md alpha 규격](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md).

| 구분 | 공식 규격의 의미 | 프로젝트 적용 |
|---|---|---|
| 목적 | 제품·브랜드의 시각 정체성을 전달하는 디자인 시스템 | 색상·서체·간격·형태·시각 상태는 루트 DESIGN.md에서 관리 |
| YAML | 선택 사항인 기계 판독용 디자인 토큰 | 기존 front matter를 유지하고 토큰의 값을 기준으로 사용 |
| 본문 | 토큰을 선택한 이유와 적용 지침 | 값의 역할과 구성 요소별 시각적 사용법을 설명 |
| 구성 | 해당하지 않는 섹션은 생략할 수 있으며, 존재하는 H2는 규정 순서를 따름 | 아래 8개 섹션을 유지하고 구성 요소별 H3는 Components 안에 배치 |

섹션 순서는 `Overview` → `Colors` → `Typography` → `Layout` → `Elevation & Depth` → `Shapes` → `Components` → `Do's and Don'ts`다.

아래 문서 분류와 프론트엔드 원칙은 **프로젝트 운영 규칙**이다. Google 규격이 이 저장소의 요구사항·번역·검증 문서 구성을 정한 것은 아니다. 일반 스킬이 DESIGN.md에 제품 목표·기능·문구까지 넣도록 권하더라도 사용자 합의와 이 기준표를 우선한다.

## 문서 분류 기준

| 판단할 내용 | 기록할 원본 | 경계 예시 |
|---|---|---|
| 무엇처럼 보이는가 | [DESIGN.md](../../DESIGN.md) | 버튼의 기본 글자색·600 굵기, 선택색, 포커스 링, 종이 크기·안쪽 여백, 스켈레톤 모양 |
| 어떻게 구현하고 안전하게 갱신하는가 | 이 문서의 프론트엔드 원칙. 모듈 책임은 [개발 안내](../operations/local_install.md#개발-검증) | DOM 의미, CSS 적용 범위, 키보드·포커스 처리, 비동기 작업 취소, 레이아웃 안정성 |
| 무엇을 하고 어떤 상태를 기억하는가 | [지원 기능](../../README.ko.md#주요-기능) | 정렬 방향 기억, 탭 고정 순서, 메모 번호 계산, A4 페이지 분할·축소 기준 |
| 어떤 말과 언어로 표시하는가 | [UI 콘텐츠 스타일 가이드](ui_content_style_guide.md)와 연결된 메시지 카탈로그 | 버튼·툴팁 문구, 한국어·영어 선택, 오류 안내 |
| 어떻게 사용·검증·추적하는가 | [사용 안내](../operations/local_install.md), [개발 안내](../operations/local_install.md#개발-검증), [개발 안내](../operations/local_install.md#개발-검증), [변경 이력](../../CHANGELOG.md) | 인쇄 설정 절차, 실제 브라우저 증거, 미검증 범위, 작업별 변경과 제출 버전 |

접근성도 책임을 나눈다. 글자 대비와 포커스의 색·두께·모양은 DESIGN.md, 접근 가능한 이름의 문구는 콘텐츠 가이드, 키보드 조작과 DOM 상태 전달은 프론트엔드 원칙에 둔다. PDF 안내에서 값의 굵기는 시각 기준, 강조할 값과 번역은 콘텐츠 기준, 안전한 텍스트 노드 생성은 구현 기준이다.

## 프론트엔드 원칙

- **시각 토큰 적용:** DESIGN.md의 기존 토큰과 구성 요소 규칙을 재사용한다. 동작 텍스트 버튼의 규칙을 모든 `button` 요소에 일괄 적용해 문서명·탐색 행·아이콘의 선택 위계를 바꾸지 않는다. 선택·비활성·테마별 반전 상태를 함께 확인한다.
- **의미와 조작:** 동작과 이동에 맞는 기본 HTML 요소를 사용한다. 키보드 접근, 현재 선택·눌림·펼침 상태, 대화상자의 포커스 이동·복귀를 실제 조작과 일치시킨다. 시각 선택만 바꾸고 접근성 상태를 남겨 두지 않는다.
- **콘텐츠 처리:** 고정 문구는 메시지 카탈로그에서 가져온다. 단순 강조는 텍스트 노드와 의미 요소로 구성한다. 사용자 Markdown 렌더링은 기존 정리 경로를 유지하며 제품 안내를 처리하려고 임의 HTML 삽입 경로를 추가하지 않는다.
- **CSS 범위:** 역할별 클래스와 기존 패턴을 사용한다. 상속·선택자 우선순위·기존 단축 속성을 확인해 색상이나 굵기가 다른 규칙에 덮이지 않도록 한다. 콘텐츠 서체와 조작 UI를 구분한다.
- **안내 강조 구현:** `pdfSettingsHint`의 `**값**` 구간은 `strong` 요소의 텍스트로, 나머지는 텍스트 노드로 만든다. 문구를 임의 HTML로 해석하지 않는다.
- **비동기 수명:** 문서 전환·닫기·완료·실패에서 예약 표시와 오래된 작업을 정리한다. 이전 문서의 렌더링 결과가 현재 문서를 덮지 않도록 유효성을 확인한다. 현행 책임은 [개발 안내](../operations/local_install.md#개발-검증)의 렌더링·갱신 설명을 따른다.
- **레이아웃과 성능:** 로딩 중 카드 높이를 유지하고, 탭을 가로로 드러내는 동작이 본문 세로 스크롤을 바꾸지 않게 한다. 크기와 표시 좌표는 현재 레이아웃을 기준으로 계산한다. 렌더러의 기존 지연 로딩과 문서 전환 시 무효화 경계를 유지한다.
- **검증:** 실제 적용된 색·굵기와 한국어·영어, Light·Dark, 긴 레이블·좁은 화면, hover·focus·선택·비활성 상태를 변경 범위에 맞게 확인한다. 실행 결과와 한계는 검증 기록에 남기며 이 문서에 완료 이력을 쌓지 않는다.

새 시각 기준은 구현 전에 DESIGN.md를 갱신한다. 기능·문구·구현 원칙이 함께 바뀌면 해당 원본도 갱신하고, 변경 이력과 검증 증거는 기존 운영 문서에 연결한다.
