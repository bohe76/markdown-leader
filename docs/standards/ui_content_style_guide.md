# UI 콘텐츠 스타일 가이드

이 문서는 Markdown Leader가 직접 표시하는 레이블, 상태, 빈 화면과 오류 문구의 기준이다. 시각 표현은 [DESIGN.md](../../DESIGN.md), 기능 범위와 동작은 [지원 기능](../../README.ko.md#주요-기능)을 따른다. 문서별 책임은 [디자인과 프론트엔드 기준표](design_frontend_boundaries.md)에서 구분한다.

## 언어 선택

- `chrome.i18n.getUILanguage()`가 반환한 Chrome UI locale이 `ko` 또는 `ko-*`이면 한국어를 표시한다. 대소문자와 `_` 구분자도 같은 locale로 처리한다.
- 그 밖의 locale과 값을 얻지 못한 경우에는 영어를 표시한다. `src/manifest.json`의 `default_locale`도 `en`을 유지한다.
- 운영체제 locale이나 문서 언어를 Chrome UI locale보다 우선하지 않는다.
- 제품이 만든 고정 문구 전체에 같은 언어를 적용한다. 사용자 Markdown, 파일명, 경로와 외부 콘텐츠는 번역하지 않는다.

## 메시지 카탈로그

- 고정 문구의 SSOT는 `src/_locales/en/messages.json`과 `src/_locales/ko/messages.json`이다. UI 코드에 같은 문구를 문자열로 중복 작성하지 않는다.
- 두 카탈로그는 같은 semantic `camelCase` key와 같은 placeholder 구조를 유지한다. 영어 메시지는 누락된 locale 항목의 fallback이다.
- placeholder에는 번역할 문장 조각보다 파일명, 시간, 개수와 원본 오류처럼 독립된 값을 전달한다.
- 문구를 추가하거나 바꾸면 한국어와 영어를 함께 갱신하고, locale 선택·fallback·placeholder 대입을 검사한다.

## 목소리와 문장

- 레이블은 `글꼴`, `Font`처럼 짧은 명사구를 사용한다. 버튼은 `설정 열기`, `Open settings`처럼 대상과 동작이 드러나는 말로 쓴다.
- 상태는 현재 작업을 먼저 쓴다. 진행 중 문구는 `문서를 여는 중…`, `Opening document…`처럼 말줄임표 `…`를 사용한다.
- 성공 상태는 선택값이나 바뀐 화면으로 충분하면 별도 알림을 추가하지 않는다. 필요한 완료 안내는 짧은 과거형으로 쓴다.
- 빈 상태는 데이터가 없다는 사실과 사용자가 할 수 있는 다음 행동만 설명한다. 오류처럼 보이는 경고 색이나 실패 표현을 사용하지 않는다.
- 오류는 발생한 일과 해결 행동을 분리해 구체적으로 쓴다. 확인하지 않은 원인을 단정하거나 내부 구현 용어를 노출하지 않는다.
- 한국어 설명은 `-습니다`체, 행동 요청은 `-하세요` 또는 `-해 주세요`를 사용한다. 영어는 sentence case와 능동태를 사용한다.

## 표준 용어

안내 위치와 표시 정보는 다음 기준을 유지한다.

- Markdown 문서만 표시한다는 안내는 시작 화면에서 제공하며 파일 목록에는 상시 표시하지 않는다.
- 문서 탭 제목의 툴팁은 파일명과 구분 가능한 경로를 표시한다. 파일명과 경로는 원문을 유지한다.

| 의미 | 한국어 | 영어 |
|---|---|---|
| 파일·폴더 탐색 | 파일 탐색기 | File explorer |
| 문서 목차 | 목차 | Outline |
| 읽기 설정 | 설정 | Settings |
| 코드 복사 동작 | 복사 | Copy |
| 코드 복사 완료 | 복사됨 | Copied |
| 본문 글꼴 | 글꼴 | Font |
| 운영체제 기본 글꼴 | 시스템 글꼴 | System font |
| 주기적 다시 읽기 | 자동 새로고침 | Automatic refresh |
| 본문 너비 | 읽기 폭 | Reading width |
| 브라우저 로컬 파일 주소 | 파일 URL | File URL |

한국어 UI에서 `Copy`와 `Copied`를 예외적으로 영어로 표시하지 않는다. 각각 `복사`, `복사됨`을 사용한다. 영어 UI에서는 `Copy`, `Copied`를 사용한다.

## 상태·빈 화면·오류

- 연결 실패 안내는 파일 이동·삭제·권한 변경 가능성과 기존 경로를 설명하되 확인되지 않은 원인을 단정하지 않는다. 공통 동작은 `다시 연결` / `Reconnect`, `목록에서 제거` / `Remove from list`, `취소` / `Cancel`이다. 제거 안내에는 현재 대상인 즐겨찾기·최근 항목을 명시하고 실제 파일은 삭제하지 않는다고 설명한다.
- 일반 오류·안내는 알림, 사용자 결정은 공통 모달로 구분한다. 연결 문제 표식은 `파일 연결 확인` / `Check file connection`, 알림 닫기는 `알림 닫기` / `Dismiss notification`를 사용한다.
- 재연결 후 보호된 메모 초안은 작성 내용이 남아 있다는 사실, 저장이 차단된 이유, 복사·취소 후 새 메모로 작성하는 방법을 안내한다. 새 파일과의 동일성이 확인되지 않았다는 뜻이며 파일 손상이나 메모 삭제로 안내하지 않는다.

- 상태 문구는 한 번에 한 상태만 보여 주고, 작업이 끝나면 필요 없는 진행 상태를 지운다.
- 비활성 컨트롤에는 가능한 경우 이유를 가까운 도움말로 설명한다. 레이블에 `비활성` 또는 `Disabled`를 반복하지 않는다.
- 검색 결과 없음, 로컬 파일 아님과 빈 폴더는 빈 상태로 다룬다. 파일 읽기 실패, 권한 거부와 저장 실패는 오류로 다룬다.
- 오류 메시지는 기존에 표시한 문서를 가능한 한 유지한 채 제공한다. 재시도나 설정 변경이 필요한 경우 사용자가 할 행동을 같은 메시지에 포함한다.
- 제품 알림에는 사용자가 확인할 결과와 다음 행동만 표시한다. 내부 오류 코드, 스택, 가상 URL과 브라우저 원문 오류는 노출하지 않는다. 개발자 콘솔에는 안정적인 오류 코드와 단계, 소스 유형, 자동 새로고침 상태, 문서명, URL, 원본 오류 이름·코드·메시지·스택을 기록한다.
- 파일을 찾을 수 없거나 파일 접근이 차단된 경우에는 해당 문서의 자동 새로고침을 중지하고 마지막으로 읽은 본문을 유지한다. 다시 연결하기 전에는 자동으로 재개하지 않는다. 일시적으로 읽을 수 없는 오류만 다음 주기에 다시 시도한다.
- `rawError`, `details`, `userMarkdown`, 파일명과 경로는 원문 그대로 표시한다. 번역, 대소문자 변경, 문장 재해석이나 다른 오류명으로의 치환을 하지 않는다. UI에 삽입할 때는 해당 출력 위치의 기존 안전한 text 렌더링을 유지한다.

## 접근 가능한 이름

- 보이는 레이블과 접근 가능한 이름은 같은 locale과 용어를 사용한다.
- 아이콘 전용 버튼은 동작과 대상을 포함한 이름을 제공한다. 방향만 설명하지 말고 `이전 검색 결과`, `Previous search result`처럼 기능을 설명한다.
- 상태나 오류를 색만으로 전달하지 않는다. 화면 읽기 프로그램이 이해할 수 있는 텍스트를 함께 제공한다.

## 정렬 컨트롤

[지원 기능](../../README.ko.md#주요-기능)의 버튼은 아이콘과 A/Z 또는 N/O 기호를 표시한다. 기호는 locale과 무관하게 유지하고 툴팁과 접근 가능한 이름은 아래 현재 상태 문구로 통일한다. N/O는 Newest/Oldest를 뜻하는 제품 내 약속이며 범용 표준 약어로 안내하지 않는다. 활성 여부는 접근성 상태로 별도 전달한다.

| 상태 | 한국어 | 영어 |
|---|---|---|
| A | 이름순 · A → Z | Name · A to Z |
| Z | 이름순 · Z → A | Name · Z to A |
| N | 수정일순 · 최근 먼저 | Modified · Newest first |
| O | 수정일순 · 오래된 먼저 | Modified · Oldest first |

위 문구는 구현 시 기존 한국어·영어 메시지 카탈로그에 반영한다. 아이콘 형태·색상은 DESIGN.md를 따른다.

## PDF 출력

- 리본 진입점과 미리보기 제목은 `PDF · A4 미리보기` / `PDF · A4 preview`, 출력 버튼은 `PDF로 저장` / `Save as PDF`다.
- 미리보기는 페이지를 준비하는 상태, 준비된 페이지 수, 필요한 리소스 또는 배치 실패를 구분한다. 실패한 미리보기에서는 출력 버튼을 활성화하지 않는다.
- Chrome 인쇄 설정은 A4·100% 배율·여백 없음·배경 그래픽 켬·머리글/바닥글 끔으로 안내한다. 구현 내부 용어는 사용 안내에 넣지 않는다.
- 인쇄 설정 안내의 강조 대상은 선택 값 6개다. `pdfSettingsHint` 카탈로그에서 `**값**`으로 구분하며 한국어·영어 모두 같은 강조 구조를 유지한다. 강조 외형은 DESIGN.md, 렌더링 방식은 [프론트엔드 원칙](design_frontend_boundaries.md#프론트엔드-원칙)을 따른다.
- 제품은 인쇄 창 이후 사용자의 저장 완료를 확인할 수 없으므로 `저장 완료`라고 표시하지 않는다. 페이지 수는 미리보기의 상태이며 저장 성공의 증거가 아니다.
